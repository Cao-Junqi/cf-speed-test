## 🛠 技术原理

### 1. 物理层建连延迟 (1-RTT TCP RTT)
*   **传统测速弊端**：传统工具通常测试 HTTPS 首包时间 (TTFB)，这包含了 TCP 握手、TLS 握手协商（额外 1-2 RTT）以及服务器计算时间，导致测出的延迟虚高（通常为 600ms+），无法体现网络层真实响应。
*   **本工具优化**：使用 `curl` 探测核心物理层指标 `%{time_connect}`（TCP 握手建连时间），只反映 **1-RTT 的双向物理时延**。该标准与 Shadowrocket (小火箭) 等主流代理软件的延迟测试完全一致，确保延迟数据的绝对真实。

### 2. 战胜 TCP 慢启动 (TCP Slow Start Window Ramping)
*   **慢启动限制**：TCP 在建连初期存在拥塞窗口限制（初始仅发送约 10 个数据包 / 14.6 KB），窗口大小随时间指数级爬升。如果测速包过小（如原版的 100KB 或 5MB），在百兆/千兆宽带下仅需几十毫秒即下载完毕，此时 **TCP 窗口还没来得及拉满，测速便已结束**，导致平均速率被严重低估。
*   **自适应智能压测**：本工具设计了 **Smart Payload** 与 **硬超时截断机制**。通过请求大体积测速包（10MB - 50MB），让 TCP 拥塞控制（如 BBR、Cubic）有充足的时间（1.5秒 - 3秒）将拥塞窗口拉满，从而测出您物理宽带的真实上限。

### 3. 多线程并行探测
*   利用 Shell 的高性能命名管道 (`FIFO`) 实现高兼容的 POSIX 信号量机制，支持 20+ 线程高并发进行延迟探测，在 10 秒内即可完成上百个 IP 的高精度延迟筛选。

## ✨ 核心功能

*   **⚡️ 自适应三档压测**：支持 `fast` (10MB 极速)、`standard` (25MB 标准)、`gigabit` (50MB 千兆深度) 三种测速大小，自适应不同带宽环境。
*   **🔄 域名维度去重聚合**：对于同一个 CNAME 域名解析出的多个 Anycast IP，在排序后采用高阶 `awk` 去重，**每个域名仅保留其延迟最低（性能最强）的那一个 IP 行**，排行榜清晰明了。
*   **🛡️ 智能多网口自动探测与直连顺序评估 (HEADLESS FRIENDLY)**：
    *   **自动物理网卡过滤**：自动在 macOS 和 Linux 系统下检索所有的活动物理网卡（如 `en0`、`en5`），智能过滤掉 `utun` (Clash)、`docker`、`lo`、`awdl` 等虚拟或环回网络适配器。
    *   **公网 Egress 连通性校验**：通过向 Cloudflare 高可用任播 Anycast 物理 IP 建立直连 TCP 握手握手，实时验证每个物理网卡的直连公网出口能力，剔除“有连接但无公网访问权限”的网卡。
    *   **轻量化一站式测速**：自动在开头仅执行一次 CNAME 解析和 API 优选节点抓取。随后自动轮询各个可连通的物理网卡，并依次绑定进行 `Phase 2` 到 `Phase 5` 的全链路延迟与带宽深度测速。
    *   **优雅的非交互式支持**：完美支持 `[ -t 0 ]` 终端检测。在 Headless 设备（如定时任务、后台脚本、NAS、无 TTY 容器）上运行多网口评估时自动切换为非交互式轮询（每网卡测速完成后自动等待 2 秒切换，无需人工干预），避免阻塞。
*   **🎨 黑白终端高对比自适应配色**：全面重构了色彩方案（如使用 HSL/Ansi256 森林深绿、琥珀深黄等），在纯黑背景与纯白背景的终端下均能保证极佳的阅读对比度。
*   **🏆 精致的一键推荐卡片**：在测速结束后，自动输出包含“分运营商最佳 IP”、“推荐 CNAME 域名”及“Cloudflare 常用 HTTP/HTTPS 支持端口参考”的精致边框卡片，极大方便配置使用。

## 🚀 使用方法

### 运行环境要求
*   **操作系统**：macOS / Linux
*   **必需依赖**：`curl`, `nslookup`, `awk`, `grep`, `sed`, `sort`, `uniq`, `bc` (脚本在运行前会自动进行工具链检查)

### 测速指令

1.  **标准模式 (推荐日常使用，默认)**
    使用 25MB 数据包测速，超强抗慢启动干扰，测试带宽上限约 **300-500 Mbps**。
    ```bash
    bash cf_speed_test.sh
    ```

2.  **千兆极致带宽深度压测模式**
    使用 50MB 极大 Payload 数据包，提供 3 秒的超长拥塞控制窗口爬升期，完美释放 **500M - 千兆** 宽带的直连极限（可测出 YouTube 30万分级节点的上限）。
    ```bash
    bash cf_speed_test.sh gigabit
    ```

3.  **极速模式**
    使用 10MB 数据包，适合弱网、移动热点或希望在 15 秒内快速体检的用户。
    ```bash
    bash cf_speed_test.sh fast
    ```

## 📅 后续规划 (DDNS 高可用自动化)

为了将该脚本进一步落地为日常网络服务的高可用保障方案，后续将规划以下核心功能：

1.  **⚙️ 后台定时检测守护进程 (Daemon Mode)**：
    *   支持以 `--cron` 或守护进程方式在家庭 Home 设备（如群晖 Synology NAS、威联通 QNAP、软路由、树莓派 Raspberry Pi 或各类 Linux 服务器）上常驻定时运行。
2.  **🔌 动态 DNS 服务商 API 联动 (Auto DDNS Upload)**：
    *   在测速筛选出综合最佳的 3 网优选 IP 或 CNAME IP 后，自动调用各大主流 DNS 解析服务商（如 **Cloudflare API**、**DNSPod / 腾讯云 DNS**、**阿里云解析 DNS**）的 API 接口。
3.  **🌐 确保高可用直连 (High Availability)**：
    *   实时、动态地更新您个人域名（如 `cf.yourdomain.com`）的 A 记录解析，将您的家庭内网、穿透节点或梯子前置路由始终指向全国各省份响应速度最快、丢包率最低、带宽上限最高的 Cloudflare 直连 IP，彻底告别手动更新！
